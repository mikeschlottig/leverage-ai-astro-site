01 — Gap Analysis

What the Research Reveals

After thorough review of all documentation and source research, here are the critical gaps and opportunities not fully surfaced in the initial report:

Undocumented Capabilities in the Initial Report

Upload API is a Full Extension Point

The /api/v1/sessions/upload endpoint is not just for remote sessions — it's the primary injection surface for agents with no native filesystem parser. Any agent can be bridged via an uploader sidecar.

Starred Sessions Are Server-Side

Stars persist in SQLite (not localStorage) — the starred_sessions table is a first-class API resource. Programmatic starring (via agent scripts) is viable: useful for auto-starring key sessions.

FTS5 Power Queries Untapped

The SQLite FTS5 engine supports MATCH with full syntax including column filters, phrase proximity, and boolean operators — none of this is exposed in the UI search bar today.

Multiple Session Directories per Agent

The claude_project_dirs array config is the cleanest WSL/Windows bridge pattern but is almost entirely undiscovered in community usage. Critical for Mike's dual-machine setup.

Skipped Files Cache is Queryable

The skipped_files table in SQLite caches parse failures. Directly querying it reveals which agent sessions are silently failing to ingest — a critical observability gap.

iframe Theme Control via postMessage

The theme:set postMessage API is a full composability hook — agentsview can be embedded as an iframe panel in other tools (e.g., a Claude Desktop sidebar or agent dashboard).

02 — Core Entry Points

Where AgentsView Can Be Extended

Based on the codebase layout, there are five independent extension surfaces. Each can be targeted without touching the others.

── AgentsView Extension Surfaces ────────────────────────────────── 1. PARSER LAYER internal/parser/ → One Go file per agent (e.g., claude.go, codex.go, gemini.go) → Implement the SessionParser interface → Register in the central registry.go / discovery config 2. DISCOVERY LAYER internal/sync/ + internal/config/ → Add default directory paths for new agents → Map environment variable overrides → Register array-config keys (for multi-directory support) 3. API LAYER internal/server/ → REST endpoints for sessions, messages, search, sync, insights → Upload endpoint for push-based ingestion (agent sidecars) → SSE endpoints for live-streaming new session content 4. FRONTEND LAYER frontend/ (Svelte 5 + Vite) → CSS custom property system (theme tokens) → Svelte component tree (session list, message viewer, dashboard) → Agent accent colors (per-agent CSS variable slots) → Branding override hook 5. INSIGHTS LAYER internal/server/ + agent CLI subprocess → Add new CLI runtimes to the insight generation dispatcher → Extend prompt templates for new agent types
Key Architectural Insight

The parser layer and discovery layer are fully decoupled. A new parser doesn't need to modify discovery code if the agent is push-based (upload API). This means Agent-Zero, which doesn't write to a standard JSONL path, can be bridged via a lightweight uploader sidecar without any Go code changes — making it a zero-fork integration path.

03 — Parser Interface

The Go Parser Contract

Every agent parser must satisfy the SessionParser interface in internal/parser/. Based on the existing parsers and schema, here is the inferred interface and normalized types: 

go// internal/parser/parser.go — the core interface every parser must satisfy

type SessionParser interface {
    // AgentName returns the canonical lowercase agent identifier
    AgentName() string

    // CanParse reports whether this parser can handle the given file
    CanParse(path string) bool

    // Parse reads the file and returns a normalized Session
    Parse(ctx context.Context, path string) (*Session, error)
}

// Session — normalized data model for all agents
type Session struct {
    ID           string
    Project      string
    AgentName    string
    FilePath     string
    StartTime    time.Time
    EndTime      time.Time
    Messages     []Message
    ToolCalls    []ToolCall

type Message struct {

04 — Agent-Zero Integration

Agent-Zero Parser Blueprint

Agent-Zero (agent0ai) is a Python-based general-purpose agentic framework using Flask + Socket.IO on the backend and a vanilla JS frontend. It stores sessions in two formats that need to be bridged:

Agent-Zero Data Architecture

StoragePathFormatContent
Chat context (JSON) /a0/usr/chats/*.json JSON per context Full AgentContext including history, tool calls, agent hierarchy, memory references
HTML session logs /a0/usr/logs/*.html Styled HTML Same output as terminal — human-readable, colored, timestamped
Scheduler tasks /a0/usr/scheduler.json JSON array Scheduled and completed task runs with context snapshots
Settings /a0/usr/settings.json JSON flat dict Model config, API keys (sensitive — don't ingest)
Integration Strategy: Two-Path Approach

Path A (Preferred): Parse the JSON context files in /a0/usr/chats/. These contain the structured History object serialized as nested JSON with all messages, tool calls, and agent hierarchy intact. This is the high-fidelity path.

Path B (Fallback): A TypeScript sidecar that watches Agent-Zero's /a0/usr/logs/ directory and converts HTML logs to JSONL, then uploads to AgentsView via the Upload API. Zero Go code required.

Path A: Direct JSON Context Parser (Go)

Create internal/parser/agentzero.go:

go// internal/parser/agentzero.go
package parser

import (
    "context"
    "encoding/json"
    "os"
    "path/filepath"
    "strings"
    "time"
)

// Agent-Zero context file schema (inferred from agent0ai/agent-zero source)
type azContext struct {
    GUID      string         `json:"guid"`
    Name      string         `json:"name"`
    CreatedAt time.Time      `json:"created_at"`
    Type      string         `json:"type"`        // "chat" | "task"
    Log       azLog          `json:"log"`
}

type azLog struct {
    Items []azLogItem `json:"items"`
}

type azLogItem struct {
    Type      string         `json:"type"`       // "user"|"agent"|"tool"|"error"
    AgentNo   int            `json:"agent"`
    Heading   string         `json:"heading"`
    Content   []azContent    `json:"content"`
    Timestamp float64        `json:"timestamp"` // unix epoch float
}

type azContent struct {
    Type    string `json:"type"`   // "text"|"tool_call"|"tool_result"
    Content string `json:"content"`
    Name    string `json:"name"`   // tool name if type==tool_call
    Params  string `json:"params"` // JSON-encoded tool params
    Result  string `json:"result"` // tool result content
}

type AgentZeroParser struct{}

func (p *AgentZeroParser) AgentName() string { return "agentzero" }

func (p *AgentZeroParser) CanParse(path string) bool {
    // Match: /a0/usr/chats/*.json (not settings.json or scheduler.json)
    base := filepath.Base(path)
    dir  := filepath.Base(filepath.Dir(path))
    return dir == "chats" &&
        strings.HasSuffix(base, ".json") &&
        base != "settings.json" &&
        base != "scheduler.json"
}

func (p *AgentZeroParser) Parse(ctx context.Context, path string) (*Session, error) {
    data, err := os.ReadFile(path)
    if err != nil { return nil, err }

    var azCtx azContext
    if err = json.Unmarshal(data, &azCtx); err != nil { return nil, err }

    session := &Session{
        ID:        azCtx.GUID,
        AgentName: "agentzero",
        Project:   azCtx.Name,
        FilePath:  path,
        StartTime: azCtx.CreatedAt,
    }

    for i, item := range azCtx.Log.Items {
        ts := time.Unix(int64(item.Timestamp), 0)
        if i == len(azCtx.Log.Items)-1 { session.EndTime = ts }

        role := mapAZRole(item.Type)
        var textParts []string

        for _, block := range item.Content {
            switch block.Type {
            case "text":
                textParts = append(textParts, block.Content)
            case "tool_call":
                session.ToolCalls = append(session.ToolCalls, ToolCall{
                    Name:     block.Name,
                    Category: mapAZToolCategory(block.Name),
                    Input:    block.Params,
                    Output:   block.Result,
                })
            }
        }

        if len(textParts) > 0 || role == "user" {
            session.Messages = append(session.Messages, Message{
                ID:        generateID(),
                Role:      role,
                Content:   strings.Join(textParts, "\n"),
                Timestamp: ts,
                Ordinal:   i,
            })
        }
    }
    return session, nil
}

func mapAZRole(t string) string {
    switch t {
    case "user":        return "user"
    case "agent":       return "assistant"
    case "tool":        return "tool_result"
    default:           return "assistant"
    }
}

func mapAZToolCategory(name string) string {
    m := map[string]string{
        "code_execution_tool":    "Bash",
        "knowledge_tool":         "Search",
        "browser_agent_tool":     "Web",
        "webpage_content_tool":   "Web",
        "call_subordinate_tool":  "Task",
        "response_tool":          "Read",
        "memory_save_tool":       "Write",
    }
    if cat, ok := m[name]; ok { return cat }
    return "Read"
}

Path B: Agent-Zero → AgentsView Sidecar (TypeScript)

Zero Go code. Runs alongside Agent-Zero's Docker container. Watches the /a0/usr/chats/ directory, converts context JSON to normalized JSONL, and uploads to AgentsView. Works immediately without forking the repo. 

typescript// agentzero-sidecar.ts — drop in alongside Agent-Zero Docker compose
import { watch } from "node:fs"
import { readFile } from "node:fs/promises"
import path from "node:path"

const CHATS_DIR    = process.env.AZ_CHATS_DIR ?? "/a0/usr/chats"
const AV_BASE      = process.env.AGENTSVIEW_URL ?? "http://127.0.0.1:8080"
const AV_TOKEN     = process.env.AGENTSVIEW_TOKEN ?? ""
const processed    = new Set<string>()

/** Convert Agent-Zero context JSON → JSONL lines */
function convertToJSONL(ctx: any): string {
  const lines: any[] = []
  for (const item of ctx.log?.items ?? []) {
    const ts = new Date(item.timestamp * 1000).toISOString()
    const role = item.type === "user" ? "user" : "assistant"
    const text = (item.content ?? [])
      .filter((b: any) => b.type === "text")
      .map((b: any) => b.content)
      .join("\n")
    if (text) lines.push({ type: "message", timestamp: ts,
      message: { role, content: [{ type: "text", text }] } })
  }
  return lines.map(l => JSON.stringify(l)).join("\n")
}

/** Upload JSONL to AgentsView upload API */
async function upload(project: string, jsonl: string) {
  const blob = new Blob([jsonl], { type: "application/x-ndjson" })
  const fd = new FormData(); fd.append("file", blob, "session.jsonl")
  const url = `${AV_BASE}/api/v1/sessions/upload?project=${encodeURIComponent(project)}`
  await fetch(url, { method: "POST", body: fd,
    headers: AV_TOKEN ? { Authorization: `Bearer ${AV_TOKEN}` } : {} })
}

/** Process a single chats/*.json file */
async function processFile(file: string) {
  if (processed.has(file)) return
  try {
    const raw = await readFile(file, "utf8")
    const ctx = JSON.parse(raw)
    const jsonl = convertToJSONL(ctx)
    if (jsonl.length > 0) await upload(ctx.name ?? "agentzero", jsonl)
    processed.add(file)
    console.log(`[sidecar] uploaded ${path.basename(file)}`)
  } catch (e) { console.error(`[sidecar] error: ${file}`, e) }
}

// Watch and process on change
watch(CHATS_DIR, { persistent: true }, (_evt, name) => {
  if (name?.endsWith(".json")) processFile(path.join(CHATS_DIR, name))
})
console.log(`[sidecar] watching ${CHATS_DIR}`)

05 — Claude Desktop

Claude Desktop Parser Blueprint

Claude Desktop stores conversation sessions in the same JSONL schema as Claude Code — the parser code is essentially free. The only delta is the session file location, which is platform-specific under Application Support.

Zero-Cost Parser Reuse

Claude Desktop uses the identical JSONL event format as Claude Code (type, message.role, message.content[], timestamp). The existing internal/parser/claude.go can parse Claude Desktop sessions without modification. Only discovery needs updating.

Discovery Registration

go// internal/config/config.go — platform-aware Claude Desktop path
func defaultClaudeDesktopDir() string {
    if env := os.Getenv("CLAUDE_DESKTOP_DIR"); env != "" { return env }
    home, _ := os.UserHomeDir()
    switch runtime.GOOS {
    case "darwin":
        return filepath.Join(home,
            "Library/Application Support/Claude/claude-code-sessions")
    case "windows":
        return filepath.Join(os.Getenv("APPDATA"),
            "Anthropic/Claude/claude-code-sessions")
    default:
        return filepath.Join(home,
            ".config/Claude/claude-code-sessions")
    }
}

The Go server exposes this at GET /api/v1/config/theme, and the Svelte app fetches it on mount and injects the values as CSS custom properties on :root. This is the blueprint for a future --theme-config PR.

13 — API Extension

REST API Extension for Agent Sidecars

For agents that can't be auto-discovered via filesystem (like Agent-Zero in Docker, or remote agents), the upload API + bearer token auth is the full integration path. No Go code changes required. 

bash# Full push-based pipeline for Agent-Zero

# 1. Enable remote access on AgentsView (enables auth token)
echo '{"remote_access": true}' > ~/.agentsview/config.json
agentsview &

# 2. Get the auto-generated token
TOKEN=$(jq -r '.auth_token' ~/.agentsview/config.json)

# 3. Test connectivity
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/v1/sync/status

# 4. Push an Agent-Zero context JSON (after conversion to JSONL by sidecar)
curl -F "file=@/tmp/az-session.jsonl" \
  -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/v1/sessions/upload?project=agent-zero"

# 5. Trigger sync to pick up the uploaded session
curl -X POST -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/v1/sync
