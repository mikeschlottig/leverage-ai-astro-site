Bug: URL.createObjectURL is not a function
The actual root cause (two layers):
Layer 1 — wrong execution context. The original code sent file content from content.js → background.js via sendMessage, then called URL.createObjectURL in the service worker. That API doesn't exist there — it's window-scoped.
Layer 2 — service worker cache invalidation is unreliable. Even after I patched background.js to use btoa instead, Chrome can keep a suspended service worker's old bytecode in memory. Reloading the extension doesn't guarantee the worker restarts with new code immediately. This is why the error persisted after the first fix.
The fix:
diff- // content.js — sends content to background.js for download
- chrome.runtime.sendMessage({ action: 'download', content, filename, mimeType }, ...)

+ // content.js — downloads directly in page context (has full Web API)
+ const blob = new Blob([content], { type: mimeType });
+ const objectUrl = URL.createObjectURL(blob);   // ✅ works here
+ const anchor = document.createElement('a');
+ anchor.href = objectUrl;
+ anchor.download = filename;
+ document.body.appendChild(anchor);
+ anchor.click();
+ setTimeout(() => { document.body.removeChild(anchor); URL.revokeObjectURL(objectUrl); }, 2000);
Why content scripts can do this: Content scripts inject into the tab's page execution context. They share the same window, document, and full Web API surface as page JavaScript. Blob and URL.createObjectURL both work there. The service worker is gone from the download path entirely.
After installing the new zip, go to chrome://extensions → find Claude Exporter → click "Remove" → reload from the new zip. Don't just "Update" — you want the service worker completely evicted.
